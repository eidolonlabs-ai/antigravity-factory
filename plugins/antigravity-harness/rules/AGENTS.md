# Software Factory Rules

Operate this workspace as a **multi-agent Software Factory** (for Antigravity). Apply these five rules to every feature, bugfix, or refactor:

1. **Plan Before Building**: Never jump straight into multi-file edits on non-trivial tasks. Inventory the repository first (`agy-factory detect`), lock shared contracts and acceptance criteria, and produce a specification with explicit disjoint file ownership before writing code (using `factory-spec-planner`, `.factory/spec.json` via `agy-factory plan --init`, or interactive planning such as `/plan` / `/grill-me`).
2. **Isolate Parallel Work**: When executing slices in parallel, give each builder an isolated git worktree (via Antigravity `/teamwork` `workspace: "share"` / `"branch"`, or `git worktree add` with `FACTORY_SLICE=<slice>`) and strictly disjoint owned files. Never assign two concurrent builders to edit the same file, enforce slice ownership mechanically with `agy-factory audit-diff --slice <slice>` (or `--allow-paths "<slice-globs>"`), and land verified slices with `agy-factory land --worktree <dir> --slice <slice>`.
3. **Deterministic Verification First**: Run `agy-factory verify --require-tests` (or the repository's build, lint, typecheck, and test commands) before declaring work complete. Never treat `NOT_RUN` as `PASS`—an unconfigured or skipped test suite is unverified, not green. Never forge or hand-edit `.factory/verify-receipt.json` or modify protected `holdout/` test suites. When changes affect a web UI, verify live user flows and console/network health using the `browser` subagent (Antigravity) or automated Playwright/headless E2E browser checks.
4. **Independent Diff & Security Review**: Run `agy-factory audit-diff` to catch secrets and injection sinks deterministically, followed by a read-only semantic code and security review of `git diff` (`factory-security-reviewer`, Antigravity's read-only `research` subagent, or an isolated read-only review task) before marking a task done.
5. **Preserve Documentation**: Keep existing comments, docstrings, type annotations, and user-facing documentation intact unless they are directly invalidated by the change.

## Local harness scope

Use one agent for small changes and native Antigravity delegation/browser features when useful. Do not build a second scheduler or change host permissions automatically. Verification receipts are unsigned freshness records; protected holdouts are not hidden. Required evidence is recorded only after actual checks, using captured digests through the CLI. Conclude with `agy-factory status --json` and a separate review/QA report. Bounded stop exhaustion means incomplete work, never success.
